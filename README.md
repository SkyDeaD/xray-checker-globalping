# xray-checker + Globalping: проверки «из мира» и «из России»

Надстройка к [xray-checker](https://github.com/kutovoys/xray-checker): берёт список
серверов из подписки, которую проверяет xray-checker, и **дополнительно** проверяет
каждый из них с российских зондов через [Globalping](https://globalping.io) —
построчно по домашним провайдерам. Отдаёт всё одним JSON: `GET /api/status` и
`GET /api/status/{key}/providers`.

Xray-checker при этом не форкается и не патчится: он запускается как есть (готовый
образ), наш сервис только читает его API и не лезет внутрь.

```
                  подписка (SUBSCRIPTION_URL)
                            |
                            v
  +-------------------------------+      +-------------------------------+
  |  xray-checker (чужой образ)   |      |  probe (этот репозиторий)     |
  |  http://xray-checker:2112     | ---> |  /api/v1/proxies (Basic Auth) |
  |  «из мира»: клиент через      |      |                               |
  |  настоящий VLESS/Reality      |      |  TCP-ping порта с зондов РФ   |
  +-------------------------------+      |        |                      |
                                         |        v                      |
                                         |  Globalping API (зонды RU)    |
                                         |        |                      |
                                         |        v                      |
                                         |  SQLite: история 31 день      |
                                         |  GET /api/status              |
                                         |  GET /api/status/{key}/         |
                                         |      providers                |
                                         +-------------------------------+
```

## Честно о том, что именно проверяется

Это важно не переоценить, поэтому прямым текстом:

* **«Из России» проверяется только доступность IP и порта.** Globalping умеет
  `ping` (ICMP/TCP), `http`, `dns`, `mtr`, `traceroute` — ничего из этого не
  говорит на VLESS/Reality. Мы отправляем `ping` с `protocol: TCP` на порт сервера
  и смотрим, ответил ли зонд.
* **Что это ловит:** блокировку по адресу или порту (SYN не проходит, таймаут или
  сброс) у конкретного провайдера.
* **Что это не ловит:** DPI и блокировку по протоколу. Рукопожатие Reality не
  проверяется.
* **Hysteria2 не проверяется вообще:** она работает по UDP, а TCP-пинг её порт не
  трогает. Такую локацию из России этим способом проверить нельзя — нужен агент
  в РФ с настоящим клиентом.
* **Разные вещи не путать:** «сервер доступен из России» и «VPN работает из
  России» — НЕ одно и то же. Второе даёт только xray-checker, и то с того хоста,
  где он стоит.

Если сервер по IP:порту доступен, а подключение не идёт — это ровно тот случай,
который такая проверка не видит (DPI). Формулируйте статус честно.

## Быстрый старт

```bash
cp .env.example .env              # ссылка подписки + пароль к метрикам чекера
cp probe.env.example probe.env    # токен Globalping + доступ к чекеру
$EDITOR .env probe.env            # CHECKER_PASSWORD в обоих файлах должен совпадать
docker compose up -d
curl -s localhost:8080/api/status | jq
```

Порт публикуется только на `127.0.0.1:8080` — наружу отдавайте через свой
обратный прокси (nginx/caddy), как вам удобно. Ссылку подписки и токен
Globalping не коммитьте: `.env` и `probe.env` уже в `.gitignore`.

Токен Globalping необязателен: без него лимит ниже, а с бесплатным аккаунтом —
выше (см. «Квоты»). Без токена источник «из России» просто выключается.

## Что отдаёт API

`GET /api/status` — публичный, кэш 60 секунд, **без адресов и портов** серверов
(иначе страница превращается в список целей для блокировки; включается флагом
`EXPOSE_TARGETS=true`, если сервис не смотрит в интернет):

```json
{
  "updated_at": "2026-10-09T18:57:29Z",
  "overall": "degraded",
  "locations": [
    {
      "key": "amsterdam",
      "name": "Amsterdam",
      "world": { "level": "green", "checked_at": "...", "latency_ms": 123, "ok": 1, "total": 1 },
      "ru":    { "level": "yellow", "ok": 15, "total": 20, "median_ms": 37, "checked_at": "..." },
      "uptime": { "pct": 99.2, "hours": 61.5 },
      "days": [{ "date": "2026-09-10", "level": "unknown" }, { "date": "2026-10-09", "level": "green" }]
    }
  ]
}
```

* `world` — что видит xray-checker (задержка у него «холодная»: новый клиент и
  соединение на каждую проверку, поэтому она больше реальной в приложении).
* `ru.level` — зелёный от 80 % ответивших зондов, жёлтый от 50 %, ниже — красный.
  `unknown` = данных нет (источник упал или зонды не взялись), а не «недоступно».
* `uptime.pct` — доля НЕ красных проверок за период с данными; меньше часа данных
  — `null`, чтобы не показывать цифру по паре замеров.

`GET /api/status/{key}/providers` — построчно по зондам последнего замера РФ:

```json
{
  "checked_at": "2026-10-09T18:57:29Z",
  "rows": [
    { "city": "Москва", "provider": "Rostelecom", "asn": 12389, "ok": true, "ms": 30 },
    { "city": "Омск",  "provider": "MTS",        "asn": 8359,  "ok": false, "ms": null }
  ]
}
```

`GET /api/healthz` — `{"ok": true}` для healthcheck.

## Настройки

`probe.env` (наш сервис):

| Переменная | Смысл | По умолчанию |
|---|---|---|
| `CHECKER_URL` | Базовый URL xray-checker | задан в compose: `http://xray-checker:2112` |
| `CHECKER_USER`, `CHECKER_PASSWORD` | Basic Auth к `/api/v1/proxies` (`METRICS_USERNAME`/`METRICS_PASSWORD` чекера) | пусто |
| `GLOBALPING_TOKEN` | Токен Globalping. Пусто — «из России» выключено | пусто |
| `RU_COUNTRY`, `RU_TAGS` | Откуда зонды: страна и теги. `eyeball-network` — домашние провайдеры | `RU`, `eyeball-network` |
| `RU_PROBES` | Зондов в одном измерении (1 зонд = 1 тест квоты) | `20` |
| `WORLD_INTERVAL` | Как часто читать xray-checker, секунды | `300` |
| `RU_INTERVAL` | Как часто опрашивать зонды, секунды | `900` |
| `TARGETS` | Свои цели: `Имя=host:port` через запятую. Пусто — берём из подписки | пусто |
| `EXPOSE_TARGETS` | Показывать адреса и порты в `/api/status` | `false` |
| `DB_PATH` | Файл SQLite | в compose: `/data/status.db` |
| `CACHE_TTL` | Кэш публичного ответа, секунды | `60` |
| `LOG_LEVEL` | `DEBUG`, `INFO`, ... | `INFO` |

`.env` (для xray-checker) — стандартный: `SUBSCRIPTION_URL`, `PROXY_CHECK_METHOD=status`
(проверка через настоящий прокси по `generate_204`), `METRICS_PROTECTED=true` и
логин/пароль к метрикам. Ссылка подписки — ключ доступа: заведите для проверок
отдельного пользователя, чтобы отзыв подписки не трогал живых клиентов.

## Локации

Локация — это то, что видно в ответе как `name`/`key`, внутри — один или несколько
адресов.

* **Из подписки** (по умолчанию): локация = группа подписки (`groupName` прокси),
  её цели — адреса и порты серверов этой группы. Появился сервер в подписке —
  появилась цель, править ничего не надо. Ключ локации — латинский слаг имени
  (`Amsterdam` -> `amsterdam`); если латиницы в имени нет (`Нидерланды`),
  ключ — `loc-` + 8 hex от имени, чтобы он не зависел от порядка серверов.
* **Вручную** (`TARGETS="Москва=1.2.3.4:443,Омск=5.6.7.8:8443"`): по одной цели на
  локацию. Так стоит делать, когда нужен результат по каждому серверу отдельно.

Почему иногда нужен ручной список: из России опрашивается только **первая** цель
локации. Это сделано ради квоты — 20 зондов на каждый адрес на каждом круге.

## Квоты Globalping

По README и OpenAPI-спецификации на 06.10.2026: без токена — 250 тестов в час и не
больше 50 зондов на измерение, с бесплатным аккаунтом — 500 тестов в час. Тест
считается за зонд, то есть `RU_PROBES=20` стоит до 20 тестов за одну проверку.

Сервис держит бюджет `450 тестов/час` и сам увеличивает интервал, если заданный
`RU_INTERVAL` в него не влезает: например, две локации по 20 зондов требуют не чаще
чем раз в 320 секунд — при `RU_INTERVAL=900` ничего не меняется, при `RU_INTERVAL=60`
интервал поднимется до 320. В логе это видно строкой «интервал замеров РФ увеличен».

На 429 от Globalping сервис читает `Retry-After` (или `X-RateLimit-Reset`) и ждёт,
а остальные локации в этом круге пропускает — «нет данных», без падения цикла.

## Запуск без Docker и разработка

```bash
python3.12 -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
CHECKER_URL=http://127.0.0.1:2112 CHECKER_USER=u CHECKER_PASSWORD=p \
GLOBALPING_TOKEN=... python -m app
```

Тесты (сеть не используется — `httpx.MockTransport` и фейки источников):

```bash
python -m pytest -q
python -m ruff check .
```

## Чего сервис не делает

* Не проверяет протоколы (VLESS/Reality/Hysteria2) — см. первый раздел.
* Не шлёт оповещений и не имеет веб-интерфейса: только JSON. Страница — ваша.
* Не ходит в панель: источник целей — подписка xray-checker или `TARGETS`.
* Не хранит больше 31 дня (чистка раз в час).
