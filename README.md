# Проверки серверов: из мира и из России

Ставится **рядом с панелью Remnawave** (на том же сервере или на другом — без
разницы), забирает из неё список серверов и показывает страницу статуса:

* **из мира** — настоящий клиент (xray-checker) подключается к каждому серверу и
  открывает тестовую страницу;
* **из России** — зонды [Globalping](https://globalping.io) у домашних провайдеров
  проверяют, открывается ли адрес и порт сервера, и показывают построчно, у какого
  провайдера не открывается.

```
+-------------------------+          +---------------------------------------------------+
|  панель Remnawave       |          |  этот сервис (один контейнер)                     |
|  GET /api/hosts         | <--------|  раз в WORLD_INTERVAL читает список серверов      |
|  GET /api/nodes         |          |  и проверяет каждый адрес:                        |
+-------------------------+          |                                                   |
                                     |  из мира:  xray-checker (профиль checker)         |
                                     |  из РФ:    Globalping, зонды country=RU,          |
                                     |            tags=eyeball-network                   |
                                     |                    |                              |
                                     |                    v                              |
                                     |  SQLite: история 31 день                          |
                                     |  GET /            страница статуса                |
                                     |  GET /api/status  JSON                            |
                                     |  GET /api/status/{key}/providers  по провайдерам  |
                                     +---------------------------------------------------+
```

## Быстрый старт

```bash
git clone <этот репозиторий> && cd xray-checker-globalping
cp .env.example .env
$EDITOR .env                 # PANEL_URL, PANEL_TOKEN, GLOBALPING_TOKEN
docker compose up -d
```

Готово: **http://localhost:8080** — страница статуса. Порт слушает только localhost,
наружу отдавайте через свой обратный прокси (и закройте его паролем, если страница
не для всех).

Что вписать в `.env`:

| Переменная | Где взять |
|---|---|
| `PANEL_URL` | адрес панели, доступный из контейнера. Панель на том же хосте — `http://remnawave:3000`; внешняя — `https://panel.example.com` |
| `PANEL_TOKEN` | панель → Settings → API Tokens → создать токен |
| `GLOBALPING_TOKEN` | [globalping.io](https://globalping.io) → Dashboard → API Tokens. Без токена проверок «из России» не будет, останется только колонка «из мира» |
| `WHITELIST_SQUAD_UUID` | необязательно: если есть squad «белых списков», его хосты покажем отдельной локацией с пометкой |

Ничего в панели сервис не меняет: три запроса на чтение.

## Честно о том, что именно проверяется

Это важно не переоценить, поэтому прямым текстом:

* **«Из России» проверяется только доступность IP и порта.** Globalping умеет
  `ping` (ICMP/TCP), `http`, `dns`, `mtr`, `traceroute` — ничего из этого не
  говорит на VLESS/Reality. Мы отправляем `ping` с `protocol: TCP` на порт сервера
  и смотрим, ответил ли зонд.
* **Что это ловит:** блокировку по адресу или порту — SYN не проходит, таймаут или
  сброс — у конкретного провайдера.
* **Что это не ловит:** DPI и блокировку по протоколу. Рукопожатие Reality не
  проверяется.
* **Hysteria2 не проверяется вообще:** она работает по UDP, а TCP-пинг её порт не
  трогает. Поэтому хосты с Hysteria2 в локации не берутся.
* **Не путать:** «сервер доступен из России» и «VPN работает из России» — не одно и
  то. Второе даёт колонка «из мира», и тоже с того хоста, где стоит чекер.

Если сервер по адресу и порту доступен, а подключение не идёт — это ровно тот
случай, который такая проверка не видит (DPI). Так и формулируйте статус.

## Что получится

Страница — таблица: **локация / из мира / из России / полоса доступности за 30 дней**.
Под каждой локацией раскрывается построчный разбор по провайдерам: город, провайдер,
ASN, результат, задержка.

Страница рендерится на сервере: без сборки, без JS, без внешних скриптов, тема
берётся из системы (тёмная/светлая). Адреса и порты серверов на неё **не попадают
никогда** — иначе публичная страница превращается в список целей для блокировки.
Хосты «белых списков» помечены отдельной строкой.

## Три источника локаций

Берётся первый настроенный:

| Источник | Переменные | Что даёт |
|---|---|---|
| Свои цели | `TARGETS="Москва=1.2.3.4:443,Омск=5.6.7.8:8443"` | по одной цели на локацию; годится без панели и без чекера |
| **Панель Remnawave** | `PANEL_URL`, `PANEL_TOKEN` | локация = страна, цели = адреса её хостов. Новая нода в панели = новая цель, код править не нужно |
| Подписка xray-checker | `CHECKER_URL` | локация = группа подписки; нужен, когда панели нет, а чекер есть |

Правила отбора хостов из панели (чтобы не выдумывать локации): хост не выключен, у
него есть адрес и порт, есть ноды, inbound хоста входит в активные inbound'ы ноды и
имеет тип `vless`, а код страны ноды известен. Служебные хосты-заглушки («Автовыбор»)
нод не имеют и отпадают сами. Неизвестный код страны — хост пропускается с
предупреждением в логе.

Из России опрашивается **первая** цель локации — это сделано ради квоты (20 зондов на
адрес на каждый круг). Нужен результат по каждому серверу — заводите по локации на
сервер через `TARGETS`.

## Настройки

Все — в одном файле `.env` (он же читается docker compose). Основные:

| Переменная | Смысл | По умолчанию |
|---|---|---|
| `PANEL_URL`, `PANEL_TOKEN` | панель Remnawave | пусто |
| `WHITELIST_SQUAD_UUID` | squad «белых списков» | пусто (не делим) |
| `TARGETS` | свои цели `Имя=host:port` через запятую | пусто |
| `CHECKER_URL`, `CHECKER_USER`, `CHECKER_PASSWORD` | xray-checker для колонки «из мира» | пусто |
| `GLOBALPING_TOKEN` | токен Globalping | пусто — «из России» выключено |
| `RU_COUNTRY`, `RU_TAGS` | откуда зонды. `eyeball-network` — домашние провайдеры | `RU`, `eyeball-network` |
| `RU_PROBES` | зондов в измерении (1 зонд = 1 тест квоты) | `20` |
| `RU_INTERVAL` | как часто опрашивать зонды, сек | `900` |
| `WORLD_INTERVAL` | как часто читать чекер, сек | `300` |
| `EXPOSE_TARGETS` | показывать адреса и порты в JSON (не на странице) | `false` |
| `DB_PATH` | файл SQLite | `/data/status.db` |
| `CACHE_TTL` | кэш публичного ответа, сек | `60` |
| `LOG_LEVEL` | `DEBUG`/`INFO`/… | `INFO` |

## Колонка «из мира» (необязательно)

Если хотите видеть второй столбец — поднимите xray-checker профилем:

```bash
cp .env.checker.example .env.checker     # SUBSCRIPTION_URL и пароль к метрикам
# в .env раскомментируйте CHECKER_URL=http://xray-checker:2112,
# CHECKER_USER и CHECKER_PASSWORD — те же, что METRICS_USERNAME/METRICS_PASSWORD
docker compose --profile checker up -d
```

Чекер поднимается готовым образом (не форк, не патчится), порт наружу не публикуется.
Локации сопоставляются с подпиской по адресу и порту: колонка «из мира» заполнится у тех
локаций, чьи адреса есть в подписке чекера, у остальных будет «нет данных» (а не
«недоступен»).
Ссылка подписки — это ключ доступа: заведите для проверок отдельного пользователя,
чтобы отзыв подписки не задевал живых клиентов. Задержка в этой колонке «холодная»
(новый клиент и соединение на каждую проверку), поэтому она больше реальной в
приложении.

## API

`GET /` — страница. `GET /api/status` — тот же набор данных в JSON (кэш 60 с, без
адресов и портов):

```json
{
  "updated_at": "2026-10-09T20:17:25Z",
  "overall": "degraded",
  "locations": [
    {
      "key": "NL",
      "name": "Нидерланды",
      "country_code": "NL",
      "whitelist": false,
      "world": { "level": "green", "checked_at": "...", "latency_ms": 123, "ok": 1, "total": 1 },
      "ru": { "level": "yellow", "ok": 15, "total": 20, "median_ms": 56, "checked_at": "..." },
      "uptime": { "pct": 96.7, "hours": 716.0 },
      "days": [{ "date": "2026-09-10", "level": "yellow" }, { "date": "2026-10-09", "level": "green" }]
    }
  ]
}
```

* `ru.level` — зелёный от 80 % ответивших зондов, жёлтый от 50 %, ниже — красный.
  `unknown` = данных нет (источник упал или зонды не взялись), а не «недоступно».
* `uptime.pct` — доля НЕ красных проверок за период с данными; меньше часа данных —
  `null`, чтобы не показывать цифру по паре замеров.

`GET /api/status/{key}/providers` — построчно по зондам последнего замера РФ:

```json
{ "checked_at": "...", "rows": [
  { "city": "Москва", "provider": "Rostelecom", "asn": 12389, "ok": true, "ms": 30 },
  { "city": "Омск",  "provider": "MTS",        "asn": 8359,  "ok": false, "ms": null }
]}
```

`GET /api/healthz` — `{"ok": true}`.

## Квоты Globalping

По README и OpenAPI-спецификации на 06.10.2026: без токена 250 тестов в час и не
больше 50 зондов на измерение, с бесплатным аккаунтом — 500 тестов в час. Тест
считается за зонд, то есть `RU_PROBES=20` стоит до 20 тестов за одну проверку.

Сервис держит бюджет 450 тестов/час и сам увеличивает интервал, если заданный
`RU_INTERVAL` в него не влезает: например, четыре локации по 20 зондов требуют не чаще
чем раз в 640 секунд — при `RU_INTERVAL=900` ничего не меняется, при `RU_INTERVAL=300`
интервал поднимется до 640. В логе это видно строкой «интервал замеров РФ увеличен».

На 429 от Globalping сервис читает `Retry-After` (или `X-RateLimit-Reset`) и ждёт, а
остальные локации в этом круге пропускает — «нет данных», без падения цикла.

## Демо на фейковых данных

Посмотреть страницу, не подключая ни панель, ни токены:

```bash
docker compose -f docker-compose.demo.yml up -d      # http://localhost:8090
docker compose -f docker-compose.demo.yml down -v    # снести вместе с данными
```

Три контейнера: заглушка (фейковые панель + чекер + Globalping), сид истории за
30 дней и сам сервис. Все адреса — `example.com`, данные вымышленные.

## Чего сервис не делает

* Не проверяет протоколы (VLESS/Reality/Hysteria2) — см. «Честно о том, что
  проверяется».
* Ничего не меняет в панели: три запроса на чтение.
* Не шлёт оповещений, не знает про инциденты и окна обслуживания.
* Не рисует карту: страница — таблица. Карта и свой дизайн — дело фронта на
  `/api/status` (там есть `key`, `name`, `country_code`, `whitelist`, `world`, `ru`,
  `days`).
* Не хранит больше 31 дня (чистка раз в час).
